# PSCC Filtering Strategy Refinement and Server-Side Workflow Changes

This folder documents selected scripts and server-side changes introduced during refinement of the PSCC somatic variant filtering strategy.

The scripts in this section are intended to document how the final filtered variant dataset was reached and how the server-side workflow was adapted during the project. They are not intended to include raw sequencing files, patient-level clinical data, credentials, or large intermediate files.

## Purpose of this section

The filtering refinement workflow had four main objectives:

1.  Improve filtering flexibility by adding optional parameters.
2.  Increase transparency of filtering decisions.
3.  Export quality-control information needed to assess sample retention.
4.  Document server-side changes made to support reproducible execution and reporting.

## Included material

This folder contains the key scripts used to refine and document the somatic variant filtering strategy.

### `filter_variants.R`

Main filtering script used to generate the refined filtered variant dataset.\
It applies the selected filtering criteria to the annotated variant table, including technical quality thresholds, recurrence/artifact filtering, population frequency filtering, cancer-gene prioritization and impact-based filtering. This script represents the core implementation of the final filtering strategy used for downstream analyses.

### `reports_list12.R`

R script used to generate summary reports for the filtered variant list.\
It was used to inspect the effect of the filtering strategy, summarize retained variants and samples and support the evaluation of the final variant dataset.

### `submit_Reports_list12.sh`

Shell script used to submit the filtering report generation step on the server.\
It documents how `reports_list12.R` was executed in the server environment and helps make the reporting step reproducible.

## Notes for reproducibility

-   This folder documents the filtering strategy refinement process, but does not include raw WES data or large intermediate files.
-   Some scripts may require objects, paths or configuration files available only in the original server environment.
-   Local paths, SLURM settings and project-specific configuration values should be adapted before reuse.
-   This documentation is intended to make the filtering rationale and server-side changes understandable without exposing private data.
